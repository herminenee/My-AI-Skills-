# Personal Document Workflow

## Purpose
Produce accurate, readable, reproducible scientific and professional deliverables while maintaining a clear separation between source data, analysis, interpretation, and presentation.

## Trigger
Use for experimental data summaries, research updates, figures, tables, presentations, reports, or conversion among CSV/XLSX/PPTX/DOCX/PDF formats.

## Workflow
1. Identify audience, goal, delivery format, source files, required sections, deadline, and constraints. If they are already known, do not ask again.
2. Inventory source files and establish provenance. Record units, dates, experiment identifiers, instrument settings, and whether values are measured, calculated, or estimated.
3. Validate data: column names, types, missing values, duplicates, unrealistic ranges, sample sizes, unit conversions, and outliers. Never silently delete or interpolate.
4. Perform traceable analysis; keep code or formulas separate from narrative. Clearly state assumptions and uncertainty.
5. Choose the artifact appropriate to the task: CSV/XLSX for analysis, figure for evidence, PPTX for weekly communication, DOCX for revision, PDF for final fixed-layout distribution.
6. Draft a concise story: goal → method → result → interpretation → limitations → next action. Distinguish observations from hypotheses and conclusions.
7. Apply personal-design principles: readable hierarchy, intentional white space, consistent visual language, and preservation of successful previous formats.
8. Verify numeric agreement across data, figures, tables, captions, and summary; check units, labels, references, date, and author attribution.
9. Review the delivered file itself (not only generating code). Verify that it opens, charts are visible, pages/slides are not clipped, and file type matches the request.
10. Handoff with the file location, what was checked, what remains uncertain, and suggested next experiment or revision.

## Specialized rules
- **Lab2Update / weekly research:** highlight what changed since last week, evidence, unresolved issues, and actionable next experiments. Do not invent progress.
- **Scientific figures:** axes must have labels and units; show uncertainty where justified; avoid implying causal conclusions from correlations.
- **Spreadsheets:** preserve raw inputs and use auditable formulas; label assumptions and outputs; avoid hard-coded unexplained numbers.
- **Word/PDF:** use consistent headings and tables; inspect final layout and pagination.
- **Slides:** one main takeaway per slide, concise copy, legible data, and clear experimental context.
- **Professional communication:** adapt to advisor, postdoc, course instructor, or wider audience without adding unnecessary formality.

## Privacy, safety, and compatibility
- Do not put unpublished research data, confidential reports, personal information, or credentials into this public-facing skill repository; store only reusable templates and synthetic examples.
- Use available environment-approved document tools; this skill does not install converters, Office, or third-party frameworks automatically.
- State when source files or render verification are unavailable; never claim a generated artifact has been checked if it has not.
- Third-party skill code should be reviewed separately before use.

## Definition of done
The correct format is delivered, key numbers reconcile with their sources, limitations are visible, and the artifact can be opened and read in its intended context.
