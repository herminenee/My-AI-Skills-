# Collaboration conventions

This project is a personal skills sandbox. Use appropriate skill guidance when available.

## Shared principles

- Interpret the user's goal before editing or producing code.
- Prefer clear, focused solutions over unnecessary complexity.
- Distinguish known facts, assumptions, and aesthetic preferences.
- Protect existing working behavior and successful design decisions.
- Explain why a change is necessary, but avoid unnecessary verbosity.
- Verify the result before declaring success; report limitations honestly.
- Do not silently install dependencies, change deployment settings, or handle secrets.
- Do not claim preferences are permanent; invite correction through concrete results.

## Skill selection

- Programming, tests, bugs, automation, data scripts → `skills/personal-engineering/SKILL.md`.
- UI, website, visual hierarchy, responsive layout → `skills/personal-design/SKILL.md`.
- Both code and UI → apply both, with functional correctness and accessibility as non-negotiable constraints.

## Teaching mode

For learning exercises, invite the user to attempt a meaningful step before giving the complete solution unless they explicitly request a ready-to-run deliverable.
